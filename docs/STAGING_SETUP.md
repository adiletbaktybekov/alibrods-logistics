# AliBros Logistics — Staging Environment Setup Guide

Руководство по настройке изолированного предрелизного контура (**Staging**) для верификации платформы AliBros Logistics перед промышленным выпуском.

---

## 1. Принцип полной изоляции Staging

Staging-окружение должно быть **полностью изолировано** от Production:
1. **База данных**: отдельная база данных (например, `alibros_staging`), полностью независимая от Production.
2. **Telegram-боты**: отдельные тестовые боты (например, `@AliBrosStageDriverBot` и `@AliBrosStageClientBot`), зарегистрированные через @BotFather. Ни в коем случае не использовать Production-токены на Staging!
3. **Google Sheets**: отдельная копия Google Таблицы для тестирования бухгалтерского учета.
4. **S3 Storage**: отдельный тестовый бакет (например, `alibros-staging-photos`) или изолированный префикс, чтобы тестовые фото не засоряли архив клиентов.

---

## 2. Подготовка инфраструктуры Staging

### 2.1. База данных PostgreSQL
1. Создайте базу данных `alibros_staging`.
2. Настройте строку подключения с SSL:
   ```env
   DATABASE_URL="postgresql://staging_user:SECURE_PASSWORD@postgres-host:5432/alibros_staging?sslmode=require"
   ```
3. Примените миграции структуры:
   ```bash
   npx prisma migrate deploy
   ```
4. Запустите сидирование каталога складов:
   ```bash
   npm run prisma:seed
   ```

### 2.2. Настройка тестовых Telegram-ботов
1. Создайте двух тестовых ботов в @BotFather:
   - Client Staging Bot (для Mini App: `https://stage.your-domain.com/miniapp`).
   - Driver Staging Bot (для рейсов и фотоотчётов).
2. Зарегистрируйте вебхук для тестового бота водителей:
   ```bash
   curl -F "url=https://stage.your-domain.com/api/telegram/webhook"         -F "secret_token=<STAGING_WEBHOOK_SECRET>"         https://api.telegram.org/bot<STAGING_DRIVER_BOT_TOKEN>/setWebhook
   ```

### 2.3. Создание первого администратора Staging
Запустите скрипт безопасной инициализации:
```bash
ADMIN_EMAIL="stage-admin@alibros.ru" ADMIN_PASSWORD="StrongStagingPassword123!" ADMIN_NAME="Staging Administrator" npm run admin:init
```

## 3. Сценарий сквозного приёмочного тестирования на Staging (UAT)

1. **Регистрация селлера**:
   - Откройте `https://stage.your-domain.com/register`.
   - Зарегистрируйте тестовую компанию селлера (ИНН, контактное лицо, телефон).
2. **Создание заявки**:
   - Создайте заявку на доставку (например, склад «Коледино» на ближайший доступный день).
   - Укажите 10 коробок.
3. **Проверка в Telegram Mini App**:
   - Откройте тестового бота селлера в мобильном Telegram.
   - Нажмите кнопку «Личный кабинет», убедитесь, что созданная заявка видна в списке.
4. **Подтверждение менеджером**:
   - Войдите в админ-панель под созданным администратором `stage-admin@alibros.ru`.
   - Перейдите в `/admin/orders`, откройте заявку и нажмите **«Подтвердить заявку»**.
5. **Привязка водителя**:
   - Зарегистрируйте тестового водителя в `/admin/drivers`.
   - Сгенерируйте код привязки (`ABL-XXXXXX`).
   - В тестовом боте водителя введите код привязки.
   - Назначьте водителя на подтверждённую заявку.
6. **Маршрут водителя и фотоотчёты**:
   - В боте водителя нажмите «Принять заявку».
   - Последовательно переведите статус: «Забрал груз» $	o$ «В пути» $	o$ «Прибыл на склад».
   - Отправьте фотографию приёмки груза.
   - Проверьте отображение фотоотчёта в карточке заказа в админке и веб-кабинете клиента.
7. **Google Sheets интеграция**:
   - Перейдите в `/admin/integrations/google-sheets`.
   - Нажмите **«Синхронизировать сейчас»**.
   - Проверьте появление строки с заказом в тестовой Google Таблице.
   - Внесите тариф (например, `12 500 ₽`) в колонку 12.
   - Повторно нажмите «Синхронизировать сейчас».
   - Убедитесь, что стоимость обновилась в PostgreSQL и отобразилась клиенту в веб-кабинете и Mini App.
8. **Завершение**:
   - В админ-панели нажмите **«Завершить заявку»**.
   - Убедитесь, что заявка перешла в архив со статусом «Завершена».
